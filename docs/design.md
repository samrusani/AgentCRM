# Design system

AgentCRM is a precision instrument for relationship work. The design reads like a well made tool: dense, calm, and immediate. Speed is part of the aesthetic. Nothing shimmers, nothing bounces, and the one expressive element is the agent panel's run ledger.

## Direction

- The subject is relationship data and agent work. Structure carries the design: rules, alignment, and type weight encode hierarchy. Decoration that carries no information gets cut.
- Depth is layered, not decorated. The app has four surface levels: the shell (nav rail, header, agent panel), the content background, cards, and raised overlays. Each level is one step lighter than the one under it in the dark appearance and one step cooler in the light appearance, so regions read apart without heavy borders. Shadows exist only as the three tokens below and only on surfaces that sit above their background; nothing glows and nothing is tinted by the accent.
- Light appearance is the default because this is a daytime professional tool. Dark appearance is a first class equal, switched by system preference with a manual override stored locally.
- One place gets the boldness budget: the run ledger in the agent panel, where agent work renders as a precise live timeline. Everything else stays quiet.
- Density over whitespace theatre. Rows are 36px, type is small but crisp, and a laptop screen shows real amounts of data.

## Color tokens

Define as CSS custom properties on `:root`, redefined under the dark scheme. Never hardcode hex values in components.

| Token | Light | Dark | Use |
| --- | --- | --- | --- |
| `--shell` | #ECEEF2 | #0E1014 | Nav rail, header, agent panel, pipeline column wells |
| `--bg` | #F4F5F8 | #15181D | Content area background |
| `--surface` | #FFFFFF | #1C2027 | Cards, tables, sheets, inputs |
| `--surface-raised` | #FFFFFF | #242933 | Popovers, command palette, menus |
| `--ink` | #1A1D23 | #E7EAEE | Primary text |
| `--ink-muted` | #5B6472 | #959DAB | Secondary text, labels |
| `--line` | #E4E7EC | #2A303A | Hairline borders, table rules |
| `--accent` | #15685B | #43B39C | Primary actions, links, active nav, focus rings |
| `--on-accent` | #FFFFFF | #15211E | Text on accent fills; white on the dark appearance accent would fail the contrast floor |
| `--accent-tint` | #E7F2EF | #1A2B27 | Selected rows, active chip backgrounds |
| `--warn` | #8A5C00 | #E0A83E | Awaiting approval, needs attention |
| `--warn-tint` | #FBF3DF | #332A14 | Approval banners and chips |
| `--danger` | #B42318 | #F0756A | Destructive actions, failures |
| `--danger-tint` | #FBEAE8 | #33201E | Failure chips |

The viridian accent is the product's color identity. Amber is reserved for exactly one meaning: a human decision is needed. Red is reserved for failure and destruction. Do not use the accent for status; status has its own two colors plus muted ink for neutral states.

Shadows are tokens, never ad hoc values: `--shadow-sm` (cards and primary buttons), `--shadow-md` (popovers, menus, the command palette), `--shadow-lg` (sheets and dialogs). Light appearance uses soft slate shadows (for example `0 1px 2px rgba(16, 24, 40, 0.06)` for sm); dark appearance uses deeper plain black ones. Shadows never carry color. Radii are three tokens: `--radius-sm` 5px (chips, small markers), `--radius` 7px (buttons, inputs, nav items), `--radius-lg` 10px (cards, sheets, popovers, wells).

## Typography

- Family: Geist variable (`@fontsource-variable/geist`) with fallback `system-ui, -apple-system, "Segoe UI", sans-serif`. If the package is unavailable, ship the system stack alone; the design must hold up on it.
- Scale: 12, 13, 14, 16, 20, 26. Base UI text is 13px with line height 1.45. Page titles 20/600. Record names in tables 13/550.
- Numbers in tables, counts, and amounts always set `font-variant-numeric: tabular-nums`.
- Sentence case everywhere: headings, buttons, labels, table headers. No all caps labels anywhere.
- No em dashes in any UI copy. Use a comma, colon, or parentheses.

## Layout

```
+----+----------------------------------+-----------+
|nav | header: workspace, search (cmd k)| agent     |
|rail+----------------------------------+ panel     |
|    |                                  |           |
| T  |  content area                    |  context  |
| R  |  (table / board / record)        |  chip     |
| P  |  left aligned, max none          |  chat     |
| S  |                                  |  run      |
|    |                                  |  ledger   |
+----+----------------------------------+-----------+
```

- Nav rail: 208px, collapsible to 56px icon rail, on the `--shell` surface with a hairline on its content edge. Destinations: Today, Leads, Relationships, Pipeline, Research. Settings pinned at the bottom. Items are 30px rounded rows (`--radius`); the active item gets a soft `--accent-tint` fill with accent text and a 500 weight, hover on the rest is a faint ink tint. No left edge bars.
- Leads and Relationships: the same screen in two framings, both with People and Organizations tabs, the same table, search, CSV import, and record sheets. Leads shows people whose lifecycle is lead and organizations with no relationship person and no opportunity; Relationships shows the rest. Each screen says what it holds in one muted line under the title (Leads: "People you have imported or captured but not yet talked to."; Relationships: "People you have a real interaction with: they replied, or a deal is moving."). The person sheet shows a Lifecycle row (above Next action): "Lead" with a quiet "Mark as relationship" action, or "Relationship" with a quiet "Move to leads" action; both work whatever caused the current value.
- New person: a "New person" button beside "Import CSV" on the People tab of both routes opens a small sheet with First name, Last name, Email, Title, and a Lifecycle select (Relationship default, Lead the other choice, on both routes); creating opens the new person's sheet. Organization empty states: Leads says "No lead organizations yet. Organizations appear here when you import or capture people who work at them."; Relationships says "No relationship organizations yet. Organizations appear here when a person there replies or a deal moves." An empty Leads screen invites an import; an empty Relationships screen says leads graduate here when someone replies or a deal moves. In-app record links (the palette, tasks, the agent panel) open the person sheet on /relationships whatever the lifecycle; the sheet loads by id and the table behind it keeps its own filter, so a lead opened this way simply has no row behind its sheet.
- Settings layout: sectioned, never one long page. A 168px sub navigation on the left lists General, Model providers, Connectors, Qualification, and Suppressions, each its own route under /settings. Items use the same rounded row language as the nav rail: the active item gets a soft `--accent-tint` fill with accent text, hover is a faint ink tint. A section whose configuration needs attention shows a small amber dot in the sub navigation. Below 900px the sub navigation becomes a horizontal strip above the content that scrolls sideways; the active item keeps its tinted fill. Links elsewhere in the app point at the specific section (for example /settings/models from a model attention notice).
- Header: 48px on the `--shell` surface with a hairline below, contains workspace name, global search field that opens the command palette (cmd k or ctrl k), and the agent panel toggle. The search field is a rounded `--surface` input with a hairline border.
- Agent panel: right side on the `--shell` surface with a hairline on its content edge, default 360px, drag to resize between 300 and 520, collapses to a 28px edge tab that keeps a status dot (accent pulse while a run is active, amber when an approval waits). State persists in localStorage. Below 900px viewport width it becomes an overlay sheet.
- Content sits on `--bg` with 20px side padding and is left aligned, no centered max width column. Each screen's primary content lives on cards: `--surface`, 1px `--line` border, `--radius-lg`, `--shadow-sm`. A table is one card; the Today screen is a grid of cards; forms and settings sections are each a card. Inside a card, tables run edge to edge of the card with row separation from 1px `--line` rules, no zebra striping, and the sticky header row stays on `--surface`.

## Components

- Buttons: primary is accent fill, `--on-accent` text, `--radius`, 28px height, `--shadow-sm`, darkening slightly on hover (a color-mix step toward black, both appearances); the pressed state uses the same step as hover, never a deeper one, so button text keeps the contrast floor. Secondary is `--surface` with 1px `--line` border and `--shadow-sm`; hover strengthens the border toward `--ink-muted`. Destructive is danger text, filled only in confirmation dialogs. A button label says exactly what it does, never "Submit". In a bulk context it carries the quantity, "Approve 10 drafts"; on a card that already names its payload, "Approve" is enough.
- Chips: evidence and status chips are 20px tall, `--radius-sm`, tint background with matching text color. An evidence chip shows source type and age, for example "imported, 3d" and opens the claim on click.
- Tables: virtualized above 200 rows (@tanstack/react-virtual). Sticky header. Row hover is `--accent-tint` at low strength. Selected rows show a left accent bar plus tint. Column headers are 12/500 `--ink-muted`.
- Pipeline board: each stage column is a well, `--shell` background with `--radius-lg` and no border, holding the stage name plus count and amount sum in a header row inside the well. Opportunity cards are `--surface` with a 1px `--line` border, `--radius`, and `--shadow-sm`; hover strengthens the border. Dragging is optional for v1; stage moves can use a menu. A dragged card lifts with `--shadow-md`.
- Pipelines: the Pipeline page header holds a pipeline select listing every pipeline by name, with the selected id riding the URL (`?pipeline=`) so a link opens the same board; the first pipeline is the default, and an unknown id falls back to it. Beside the select sit quiet actions: "New pipeline" opens a small sheet with Name (required, prefilled with the chosen template's pipeline name until edited by hand) and a Template radio list showing each template's one line description and stage names, primary button "Create pipeline", and creating switches the board to the new pipeline; "Rename" opens a small sheet with the name prefilled; "Change template" opens the template sheet for the selected pipeline; "Delete" asks an inline confirm and is disabled with its reason while the pipeline holds any deal or is the last one ("This pipeline still holds N deals." or "This is the only pipeline."); when the deal count cannot be read the reason says so instead, an open confirm closes whenever the board changes underneath it, and the Rename sheet carries the version from when it opened, so an edit from another tab conflicts instead of being overwritten. The board and table always show the selected pipeline only.
- New opportunity: a primary "New opportunity" button in the Pipeline page header opens a right sheet (same frame as the record sheet) with Name (required), Person (search picker, optional), Organization (search picker, optional, prefilled from the chosen person's organization and still editable), Pipeline (select of every pipeline, preselected to the board being viewed), Stage (select of the chosen pipeline's stages, first stage preselected; changing the pipeline resets the stage to that pipeline's first), and Amount (optional number with a currency select defaulting to USD). The person sheet's Opportunities section and the organization sheet's Opportunities section each carry a quiet "New opportunity" action that opens the same sheet with that record prefilled. When the selected stage is past the first, one muted line states that creating the deal marks the linked person as a relationship. The primary button reads "Create opportunity"; on success the sheet closes and the new opportunity's sheet opens on the Pipeline route. Inline errors stay in the sheet and end with what to do next; a missing name disables the button rather than erroring after the fact. An organization filled automatically from the chosen person follows the person: changing or clearing the person replaces or clears it, while an organization the user chose or cleared by hand is never overwritten. Opened from a record sheet, the pipeline select defaults to the first pipeline.
- Record picker: a single line input that searches as you type (debounced, served by the search endpoint), listing up to 8 matches below in a `--surface-raised` popover with `--shadow-md`: the record name plus its organization or domain in muted text. Arrow keys and enter choose, escape closes, and a chosen record renders as the name with a quiet clear control in place of the input. Enter inside the picker never submits the surrounding form, and a selection applies only once the list reflects the typed text and the search has settled with no fetch in flight, so Enter never takes a stale match from the debounce window or from a background refetch, and never a different option than the one highlighted. It is a combobox with the proper roles. By default it only picks existing records and never creates one. A call site may turn on a create affordance (today: the person sheet's Organization row, organizations only), which appends one last option reading `Add "<typed text>" as a new organization` once the list reflects the typed text and the search has settled, including when nothing matched; an existing match never hides it, since names are not unique. Arrow keys reach it and Enter chooses it like any option. Choosing it creates the organization with the typed text trimmed as its name, kind company, and nothing else set, then picks it in one step; the picker's input and options are disabled while the create is in flight, the popover stays open, and a repeated Enter or click while it is in flight never fires a second create. Text that leaves nothing after trimming whitespace and invisible format characters counts as empty, so an invisible name is never searched, offered, or created. A create failure shows in the popover's note line as a full sentence even when the server's wording lacks a final period, ends with what to do next (fix the name for a validation refusal, try again for anything else), and leaves the typed text in place.
- Today: each section (Approvals waiting, Outbox, Follow-ups, Replies, Tasks due and overdue, Active runs) is its own card in a grid, two columns when the Today area itself is at least 760px wide and one below, keyed to the container width (not the viewport) so an open agent panel or nav rail counts against it. A card's header row holds the section title at 13/600 and, when the section has items, a muted tabular count. Empty sections keep their one sentence and action inside the card.
- Record detail: opens as a 480px right sheet over the table (not a new page), on `--surface` with `--shadow-lg` and a hairline on its leading edge, over a scrim that darkens the content behind it (translucent black in both appearances, never the ink token, which is pale in the dark appearance; no blur) with name, fields, evidence chips, then a "Notes and activity" section (the note form directly under its title, then the follow-up rule line when one exists, then the timeline), then opportunities and tasks. Notes sit above opportunities and tasks because jotting a note is the most common act on an open record. The opportunity sheet on the pipeline follows the same pattern, a "Notes and activity" section with its own note form below the status form. Esc closes.
- Profile fields: person sheets show LinkedIn and X rows among the fields, organization sheets a LinkedIn row; the value renders as a link opening in a new tab, shortened to the path (`/in/jane-doe`, `/company/acme`), editable like any field, with its evidence chip. The organization Domain field renders the same way: the stored domain as the visible text, linking to `https://<domain>` in a new tab, still editable. A stored value that is not a bare host with at least one letter (anything carrying a scheme, path, userinfo, port, or a purely numeric address) renders as plain text, never as a link.
- Enrich (organizations): the organization sheet shows the same "Enrich" button beside Fields with the muted line "Runs one company lookup on your Apify account."; it is disabled only when Apify is not connected ("Connect Apify in Settings to enrich"). The suggestions list behaves exactly like the person one, and when the lookup matched by name the run detail line above the list says which company the lookup found, so a wrong match is visible before any Accept.
- Organization on the person sheet: the Organization row is editable like any field. It shows the linked organization's name as a link opening that organization's sheet, or "None" in muted text, with the standard pencil edit control beside either. Editing swaps the value for the organization record picker in place: choosing an organization saves it immediately and the row, subtitle, and opportunity prefill follow after the refetch; Escape or clicking away cancels without saving. While the person has an organization, edit mode also shows a quiet "Remove organization" action that saves None. The picker here has the create affordance on, so a company not yet in the CRM is added and linked without leaving the sheet. While the row is editing, Escape never closes the sheet: it closes the match list first, then cancels the edit, and while a create or save is in flight both Escape and clicking away do nothing until it finishes. A version conflict uses the editable field's own wording with a reload action and refetches the person in place, so a second pick without pressing reload still carries the current version. Any other save failure states that the organization was not changed; when the create succeeded but the link failed, the failure instead names the created organization and says to pick it from the search to finish linking, so the user never creates it twice.
- Enrich: every person sheet shows an "Enrich" button beside the Fields title. With a LinkedIn profile saved the muted line reads "Runs one profile scrape on your Apify account."; without one it reads "No profile saved, so this searches LinkedIn by their name on your Apify account. Check the match before accepting." Disabled with a reason only when Apify is not connected ("Connect Apify in Settings to enrich"). A finished name lookup renders the run's own detail line naming who the search found above the suggestions, so the user judges the match before accepting anything. A conflict on accepting a name lookup suggestion shows the server's own reason rather than the generic field-changed wording, and when the connector state cannot be read the button's reason says the check failed instead of claiming Apify is not connected. While the run is open the button reads "Enriching" and is disabled. Finished suggestions render as a "Suggestions" list between Fields and Qualification: each row shows the field name, the scraped value, and an Accept button; one "Dismiss" text button clears the rest. The button stays disabled from the click until the next enrichment read lands, and while an accept or dismiss is in flight every Accept and Dismiss control is disabled, so a fast second click cannot race the refetch. Accepted values appear in Fields immediately with their evidence chip. A run that found nothing new shows one muted line with the run's own detail instead of an empty list, and a failed run shows its failing detail the same way until the next run; a run whose suggestions were all accepted or dismissed shows nothing.
- Run ledger (the signature element): vertical timeline in the agent panel and on the Research screen. Each step is a row with a 8px status marker (hollow ring queued, accent pulse running, filled accent done, amber pause for waiting, danger for failed), title, and a muted detail line. The active step's ring pulses gently, the only unprompted motion in the product, disabled under `prefers-reduced-motion`. Counts render as plain tabular numbers, no progress bar theatrics.
- Approval card: warn tint background, title, payload summary, and two buttons, "Approve" and "Reject". After deciding it collapses to one line with the decision and timestamp.
- Command palette: center top overlay on `--surface-raised` with `--radius-lg` and `--shadow-md`, groups People, Organizations, Opportunities, Actions. Keyboard first, arrow and enter navigation.

A review the setting decided shows as approved with the wording "Auto accepted" where a decided review names its decider.

One muted line states what never changes: people, organizations, opportunities, tags, claims, tasks, and history stay as they are; only the pipeline stages and, if chosen, the qualification rules change. Errors (unmapped stages, version conflict) show inline.

## Motion

- 120 to 160ms ease out transitions, only in response to a user action: sheet open, palette open, panel collapse, approval collapse.
- Hover and press states may transition background, border, and shadow at the standard duration. Nothing moves, scales, or slides on hover.
- One exception: the active run step's pulse.
- Respect `prefers-reduced-motion: reduce` by disabling all transitions and the pulse.
- Never animate table rows, page loads, or numbers counting up.

## Performance rules

- Interactions render from cache first (TanStack Query), then reconcile. Stage moves apply optimistically and roll back visibly on failure. Send style actions are never shown optimistically.
- Virtualize long tables. Request only the fields a view renders.
- No layout shift from fonts: `font-display: swap` with metric compatible fallback, or system stack.
- Keep the main bundle lean. No component library, no CSS framework, no icon megapack. Hand write the CSS on the tokens above; use a small set of inline SVG icons (16px, 1.5px stroke) defined once.

## Voice

- Interface copy is calm and specific. "No model connected. Runs are simulated until you add one." beats any enthusiasm.
- Errors state what happened and what to do next. They do not apologize and they are never vague.
- An agent's uncertainty is stated as data: "2 of 12 addresses unverified", never hidden.
- Simulated or demo content is always labelled as such where it appears.

## Accessibility floor

- Visible 2px accent focus ring on every interactive element, offset 1px.
- All text at least 4.5:1 contrast against its background in both appearances.
- Full keyboard operation: tables, palette, approvals, and panel are reachable and operable without a mouse.
- Status is never conveyed by color alone; markers differ in shape or carry text.
